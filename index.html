Platforms

Same game, different hurdle

Both apps follow the same rules — same folder layout, same JVM arguments, same GLFW mapping. What differs is what the OS permits.

🤖 Android

  • Install the APK and you're done
  • No JIT setup needed
  • Four renderers plus custom Vulkan drivers
  • Mouse pointer capture
  • Android 8.0+ · arm64-v8a

🍎 iOS

  • Sideload, then enable JIT
  • TrollStore does it in one step (iOS ≤ 17.0)
  • Above that, StikDebug — a computer once only
  • Iris shaders run on the MobileGlues renderer
  • MC 26.3 — SDL3 windowing and input, rendered with Vulkan (MoltenVK)
  • iOS 17.0+ · arm64
iOS forbids apps from generating machine code at runtime, and Java runs exactly that way — without a debugger attached to lift the restriction, the game stalls partway through boot. So how you install decides whether JIT can ever work: signing services that don't ask for your UDID use a distribution certificate, and no tool will enable JIT on one.
Architecture

Three bridging layers

Bridging a desktop Java game to mobile hardware. That's the whole trick.

01☕

JVM boot

Starts the bundled JRE with JNI_CreateJavaVM and calls the game's main() directly, picking Java 8 / 17 / 21 / 25 to match the version.

02🎨

Graphics bridge

Translates desktop OpenGL through Zink, GL4ES, Krypton or MobileGlues onto the mobile GPU — falling back automatically when a path fails.

03🕹️

I/O bridge

Wires the GLFW windowing and input API to Android Surface, touch and key events — keyboard, mouse and gamepad ride the same path.

Reuses PojavLauncher's proven native bridges and adapts parts of ZalithLauncher 2's launch orchestration, then adds a Compose UI, content integration and crash recovery.

Graphics

Four renderers

On Android, a failing Zink path falls back natively: Freedreno → Panfrost → GL4ES. On iOS, MobileGlues is the default — and the only one shaders run on.

Renderer How Best for Platform
Zink 🌋Vulkan → OpenGL Modern GPUs, 1.17+Android
GL4ES 🕹️OpenGL → GLES 2.0 Older versions (≤1.12), devices without ZinkAndroid · iOS
Krypton ⚛️OpenGL → GLES 3.x Shaders plus broad coverage; bundledAndroid
MobileGlues 🚀OpenGL 4.x → GLES 3.2 Best shader performance; built into both appsAndroid · iOS default
Custom Vulkan drivers (Turnip and friends) are not distributed by this project. Get them from a trusted source — official Mesa, K11MCH1/AdrenoToolsDrivers — and import the zip yourself.

Under the hood

Nine steps to start one game

  1. Pick a version — fetch Mojang's version_manifest.json
  2. Pick a loader — query the Fabric / Forge / NeoForge meta APIs
  3. Download — client jar, libraries and assets
  4. Install the loader — merge libraries, flatten into InstanceMeta
  5. Extract the JRE — Java 8 / 17 / 21 / 25 to match the MC version
  6. (First Forge run) a separate process patches the client jar, then exits
  7. Load the renderer — load the selected .so and set environment variables
  8. Boot the JVM — flamejvm.cpp::bootMinecraftJVM → JNI_CreateJavaVM
  9. Start the game — mainClass.main(args)
Why step 6 is its own process: JNI_CreateJavaVM can only be called once per process. Running Forge processors inside the game JVM freezes the classpath before the patched jar exists.

Scope

What works, what doesn't

Stated honestly — including what does not work.

✅ Works

  • Vanilla, Fabric, Forge, NeoForge (Quilt via modpacks)
  • The full Microsoft sign-in flow
  • Java 8 / 17 / 21 / 25, selected and extracted automatically
  • Shader packs and custom Vulkan driver import
  • Simple Voice Chat and friends, via the microphone bridge
  • Terracotta P2P multiplayer — direct, with no relay server
  • The latest stable release, 26.3 (iOS) — Android up to 26.2

⛔ Does not work

  • MC 26.3 on Android — the game moved from GLFW to SDL3. iOS is done; Android is in progress.
  • Android: the game's Vulkan backend — there is no VkSurfaceKHR creation path. Run with OpenGL.
  • Mods bundling desktop-only natives — auto-disabled by renaming, not deleting, so modpack integrity survives
  • 32-bit devices — arm64 only
  • iOS: re-attaching JIT on every version switch — a JVM starts once per process, and JIT is a property of the process. There is no way around it.
  • Joining an Online LAN room on iOS — the entitlement for a virtual network device cannot be signed with a free account, so the address goes in by hand. Hosting works normally.
